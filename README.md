# 我們的地方

一個只屬於你們這群人的小空間：要邀請碼才能進來，名稱、顏色、群規、每日儀式都由你們自己決定。

這是**模板**：每一群人各自架一份，資料存在你們自己的資料庫，不經過任何第三方平台。

## 有什麼

- **聊天**：一個共用的聊天室。
- **今天**：每日一個話題（由管理者或所有人出題），加上一個每日儀式按鈕（例如「點一盞燈」），看得到今天有誰來過。
- **語錄**：聊天裡說得好的話，點一下就能收進語錄，慢慢累積成大家共有的記憶。
- **管理**：同意或移除成員、刪除訊息、修改空間設定、更換邀請碼。

## 十分鐘架好你們的空間

### 1. 建立資料庫（Supabase，免費方案即可）

1. 到 [supabase.com](https://supabase.com) 註冊，按 **New project**，名稱自取，地區選 **Northeast Asia (Tokyo)** 或 **Southeast Asia (Singapore)**。
2. 建好後，左側選 **SQL Editor**，把 `schema.sql` 整份貼上，按 **Run**。
3. 在 SQL Editor 再執行一行（把兩個碼換成你自己的）：
   ```sql
   select setup_space('給成員的邀請碼', '只有你知道的管理碼');
   ```
   - 邀請碼至少 6 個字，管理碼至少 8 個字，兩者不能相同。
   - **管理碼不要給任何人**，用它加入的人會成為管理者。

### 2. 取得連線資料

左側 **Project Settings → API**（或 **API Keys**），複製：
- **Project URL**（像 `https://abcdefgh.supabase.co`）
- **anon public key**（`eyJ` 開頭的長字串），或新版的 **publishable key**（`sb_publishable_` 開頭）

> 不要複製 `service_role` 或 `secret` key，那把是最高權限，絕對不能放進網頁。

### 3. 放上網頁（GitHub Pages）

1. 在 GitHub 建一個新的 repo（Public），上傳 `index.html`、`config.js`。
2. 在 GitHub 上編輯 `config.js`，填入第 2 步的網址和金鑰，Commit。
3. **Settings → Pages**，Source 選 `Deploy from a branch`，Branch 選 `main` / `(root)`。
4. 一兩分鐘後打開網址，用**管理碼**加入，你就是第一位管理者。
5. 到「管理」分頁設定名稱、顏色、群規和儀式，再把網址和**邀請碼**傳給成員。

## 安全設計

- 資料表完全不對外開放。網頁只能呼叫資料庫裡的函式，每個函式都會先核對成員身分。
- 知道網址、拿到金鑰的人，沒有邀請碼也讀不到任何訊息。
- 邀請碼和管理碼只存雜湊值，資料庫裡看不到原文。
- 被移除的成員立刻失去存取權。

## 限制

- **身分綁在裝置上。** 沒有帳號密碼；換手機或清除瀏覽器資料後，要用邀請碼重新加入，會變成新成員（舊訊息還在）。
- **不是即時推播。** 聊天每 3 秒更新一次，關掉網頁就不會收到通知。
- **沒有圖片與檔案。** 只有文字。
- **防猜碼只有基本措施。** 邀請碼請用不容易猜的字串，外流時到「管理」更換。
- **Supabase 免費專案一週沒有使用會被暫停**，到後台按一下就能恢復，資料不會消失。

## 責任

這個空間的內容與成員由架設者（管理者）負責管理。模板作者不經手、也看不到任何一個空間的資料。
